# 線形探索

## 1. 概要

線形探索は、配列やリストの**先頭から順に見ていき、目的の値を探す**探索方法。  
最も基本的な探索の形であり、整列済みである必要はない。

今回のトピックでは、次の内容を確認する。

- 先頭から末尾まで順に確認する流れ
- target と一致した時点で探索を終了する流れ
- 見つかった場合と見つからない場合の違い
- 比較回数の増え方

## 2. 基本の動き

線形探索では、先頭要素から 1 つずつ値を確認する。  
今見ている値が target と一致したら探索終了、一致しなければ次の要素へ進む。

イメージ:

```text
[12, 7, 25, 3, 18, 30, 5]
 target = 30

12 -> 7 -> 25 -> 3 -> 18 -> 30
                     ここで一致
```

整列済みである必要がないため、どのような並びの配列でも使える。  
一方で、目的の値が後ろにある場合や存在しない場合は、最後まで確認する必要がある。

## 3. 処理の流れ

このトピックでは、次の順で線形探索の動きを確認する。

1. 入力配列を決定する
2. 探索対象値を決定する
3. 配列の先頭から順に値を確認する
4. 各要素ごとに target と一致するか判定する
5. 一致した時点で index を返して探索を終了する
6. 最後まで一致しなければ未発見として終了する

trace あり実行では、どの index をどの順に確認したかを出力する。  
そのため、探索が「前から順番に進む」ことを見て確認できる。

## 4. 計算量

### 見つかった場合

- 最良: O(1)
- 平均: O(n)

先頭付近で見つかればすぐ終わる。  
一方で、平均的には何件か順に確認する必要がある。

### 見つからない場合

- 時間計算量: O(n)
- 空間計算量: O(1)

最後まで全件確認する必要があるため O(n)。  
補助的に使う変数は定数個なので O(1)。

## 5. メリット / デメリット

### メリット

- 実装が単純で分かりやすい
- 整列済みでなくても使える
- 配列でも連結リストでも考え方が同じ

### デメリット

- データ量が増えると探索回数も増えやすい
- 後ろの要素や未存在の値を探すと重い
- 二分探索やハッシュに比べると高速化しづらい

## 6. Java実装のポイント

- `for` 文で先頭から末尾まで順に走査する
- 各要素ごとに `==` で target と比較する
- 一致した時点で `return` して探索を終了する
- trace 用の出力は本体処理と分け、結果オブジェクトにまとめる

## 7. コアとなる処理・重要なコードの見どころ

線形探索学習で重要なのは、**先頭から順に確認し、一致した時点で終了する**点。

### 探索本体の見どころ

```java
for (int i = 0; i < values.length; i++) {
    if (values[i] == target) {
        return ...;
    }
}
```

ここが線形探索のコア処理。  
先頭から末尾まで順番に比較しており、見つかればその場で終了する。

### 学習時に特に見たい点

- 配列の並びに依存せず使える
- index が 1 つずつ進む
- 見つからない場合は最後まで走査する

## 8. 実行例

### 基本実行

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic linear-search
```

### trace あり実行

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic linear-search --trace
```

### 任意入力

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic linear-search --input 12,7,25,3,18,30,5 --target 30
```

### size 指定

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic linear-search --size 20 --target 19
```

### 出力で確認する内容

- 入力値
- 探索対象値
- found
- index
- comparisons
- trace 時の確認順
