# ハッシュテーブル

## 1. 概要

ハッシュテーブルは、**値やキーから計算したハッシュ値を使って、格納位置を素早く決める**データ構造。  
今回のトピックでは、学習用に単純化した自前実装を使い、次の内容を確認する。

- 値からバケット位置を求める流れ
- 同じバケットへ値が集まる衝突の考え方
- バケット内を連結して保持する流れ
- `contains` による存在確認

## 2. 基本の動き

ハッシュテーブルでは、値そのものを順番に並べて探すのではなく、まずハッシュ関数で **どのバケットを見るか** を決める。  
今回の実装では、学習用として次のような単純な式を使う。

```text
bucketIndex = value % bucketCount
```

たとえば bucket 数が 7 の場合、値 10 は `10 % 7 = 3` なので `bucket[3]` に入る。  
値 17 も `17 % 7 = 3` なので、同じ `bucket[3]` に入る。これが衝突。

```text
10 -> bucket[3]
17 -> bucket[3]  // 衝突
24 -> bucket[3]  // 衝突
```

衝突した場合、今回の実装では同じバケット内を単方向連結でつなぐ。

## 3. 処理の流れ

このトピックでは、次の順でハッシュテーブルの動きを確認する。

1. 入力値を順に読み取る
2. 各値からバケット位置を計算する
3. 対応するバケットが空なら先頭ノードとして追加する
4. 対応するバケットに既に値があれば、同じバケット内の末尾へ連結する
5. 構築後に、各バケットへどの値が入ったかを確認する
6. `contains` で対象値のバケットを求め、そのバケット内だけを順に確認する

trace あり実行では、追加時にどのバケットへ入ったか、検索時にどの値を確認したかを出力する。  
そのため、線形探索と違って、**まず見る場所を絞ってから確認する**流れを見て確認できる。

## 4. 計算量

### 平均的な考え方

- 追加: O(1)
- 存在確認: O(1)

ハッシュ値から見るバケットを絞れるため、平均的には高速に扱える。

### 衝突が多い場合

- 追加: O(n)
- 存在確認: O(n)

同じバケットへ値が偏ると、バケット内を順に確認する必要があり、線形探索に近づく。  
今回の学習用実装では、あえて衝突が起きる入力も使い、平均ケースと最悪ケースの違いを意識しやすくしている。

## 5. メリット / デメリット

### メリット

- 平均的には高速に存在確認できる
- どの位置を見るかを先に絞れる
- Set / Map の内部イメージにつながる

### デメリット

- 衝突が起きるとバケット内の確認が必要になる
- ハッシュ関数やバケット数の設計に影響される
- 配列や連結リストより仕組みが少し複雑

## 6. Java実装のポイント

- 学習用として、標準ライブラリの `HashSet` / `HashMap` を直接使う前に、自前の簡易ハッシュテーブルを実装する
- バケット配列は `Entry[]` で持つ
- 衝突時は `Entry.next` で同じバケット内を連結する
- `contains` では、まずバケット位置を計算してから、そのバケット内だけを順に確認する
- runner 側では入力決定と表示整形を担当し、ハッシュテーブル本体の実装は `algorithms/` に分離する

## 7. コアとなる処理・重要なコードの見どころ

ハッシュテーブル学習で重要なのは、**値からバケット位置を決めること** と、**衝突時に同じバケット内で処理すること**。

### バケット位置計算の見どころ

```java
private int bucketIndex(int value) {
    return Math.floorMod(value, buckets.length);
}
```

ここがハッシュテーブルの入口。  
値からどのバケットを見るかを決める。

### 追加処理の見どころ

```java
int bucketIndex = bucketIndex(value);
Entry head = buckets[bucketIndex];
```

まずハッシュ値からバケット位置を求め、そのバケットが空かどうかを確認する。  
空でなければ衝突として、同じバケット内へ追加する。

### 検索処理の見どころ

```java
Entry current = buckets[bucketIndex];
while (current != null) {
    if (current.value == target) {
        return ...;
    }
    current = current.next;
}
```

線形探索のように全体を最初から見るのではなく、まず対象バケットへ絞り、その中だけを順に確認する点が重要。

## 8. 実行例

### 基本実行

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic hash-table
```

### trace あり実行

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic hash-table --trace
```

### 任意入力

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic hash-table --input 10,17,24,31,38,45,52 --target 31
```

### size 指定

```bash
java -cp out io.github.seiya_matsuoka.linearsearchhashing.App --topic hash-table --size 8 --trace
```

### 出力で確認する内容

- 入力値
- 探索対象値
- bucket 数
- 衝突回数
- 各 bucket の状態
- `contains` の結果
- trace 時の追加順・検索順
